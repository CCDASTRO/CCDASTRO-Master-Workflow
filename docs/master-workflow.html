CCDASTRO Master Workflow

Existing PixInsight tools in one place, from session datasets to masters.

Install first

v0.4.0 is signed; PixInsight verified both the script and update-manifest signatures for CCDASTRO. Adds PixInsight 1.9.6 choices for subframe analysis, blind solving, astrometric/lunar registration, mosaic preparation and preprocessing-log analysis. Install v0.4.0 through the repository below.

v0.3.2 adds GPUStacker to Batch preprocessing. Install GPUStacker separately, then choose it and click Open tool. Configure AstroPipeline, input frames and output in GPUStacker and start processing there; session folders are not loaded automatically.

v0.3.1 packaging update adds PI 1.9.6 eligibility. The unchanged signed launcher retains its 0.3.0 title. After a full PI replacement, reinstall this repository package and rescan src/scripts/CCDASTROMasterWorkflow through Script → Feature Scripts if the menu is missing.

v0.3.0 signed development release with three-master HDR preparation, automatic exposure-group detection, NBExtractPI and ImageSolver shortcuts. Install through the repository below or download the release ZIP.

PixInsight Update Manager

  1. Open Resources → Updates → Manage Repositories and add:

    https://raw.githubusercontent.com/CCDASTRO/CCDASTRO-Master-Workflow/main/updates/

  2. Choose Resources → Updates → Check for Updates, install Master Workflow and restart PixInsight when requested.
  3. Open Script → CCDASTRO → Master Workflow. If missing, use Script → Feature Scripts to scan src/scripts/CCDASTROMasterWorkflow under the PixInsight installation and regenerate the feature list.

Keep this repository enabled for later updates. It is separate from our post-processing Workflow Manager.

Manual installation or testing

  1. Download the release ZIP and extract it. In its src/scripts/CCDASTROMasterWorkflow folder keep all three JavaScript files and the signature together. A GitHub source ZIP has a pixinsight folder instead.
  2. Choose Script → Execute Script File and select CCDASTROMasterWorkflow.js. Do not run MasterTools.js separately.
  3. For a permanent menu entry add the containing folder through Script → Feature Scripts. For upgrades replace the matching script, include and signature together; keep saved JSON session plans.

v0.4.0 native UI checked on PixInsight 1.9.6/V8. Existing scripts must be installed separately. No vendor files are included.

Choose a method, then use its own controls.

  1. Select an acquisition profile and optionally record the session root, output destination and per-filter folders.
  2. Choose a tool from the relevant dropdown and click Open tool.
  3. Configure the actual inputs, outputs and processing options in that tool, then run it explicitly.
  4. Reopen Master Workflow for the next stage. Folder entries and choices are remembered; save/load JSON plans for different sessions.

Folder entries are a checklist. They are not automatically transferred into tools. This launcher does not process pixels or create masters by itself.

Save important process parameters as icons before opening a new native interface instance. Tools open with their own settings; the launcher does not control their processing.

Five acquisition profiles

  • Mono LRGB with optional Ha, OIII and SII.
  • OSC broadband.
  • OSC broadband plus Ha/OIII filter sessions.
  • OSC broadband plus Ha/OIII/SII filter sessions.
  • OSC broadband plus separate mono Ha, OIII and SII data or masters.

Calibrate filter datasets separately as required, select matching flats and register intended combination masters to a common reference. RGB channel extraction does not automatically isolate Ha/OIII/SII from a filter image; use the existing extraction method appropriate to the camera and filter.

Extract Ha/OIII from L-Ultimate OSC data

New in the signed v0.2.1 development release.

  1. Calibrate, debayer, register and integrate the dual-band sessions. Keep the RGB master linear.
  2. Open Plate solving → ImageSolver and solve the master. Configure local Gaia DR3/SP XPSD spectrum database files in the Gaia process as required by NBExtractPI.
  3. Open OSC narrowband extraction → NBExtractPI. The separately installed tool is detected in its standard location or installed Lighthouse subfolder.
  4. Inside NBExtractPI select the linear plate-solved RGB master, choose Ha / OIII and set both bandwidths to 3 nm for L-Ultimate.
  5. Click Calibrate Mixing Matrix, review the report, then explicitly click Extract Channels. Inspect and save the resulting mono Ha/OIII images.
  6. Supply separately acquired SII data for an SHO combination. Register all intended masters to common geometry and use the existing channel-combination tool.

L-Ultimate passes Ha and OIII; it does not record SII. This uses NBExtractPI's existing extraction model, not plain RGB channel splitting. Our launcher neither selects its target nor runs extraction. NBExtractPI and its Gaia database prerequisites are separately installed.

NBExtractPI credits its method to Franklin Marek / Seti Astro's NBExtract. Its independently maintained PixInsight implementation is not bundled. Optolong L-Ultimate specifications.

Prepare an HDR composition from three masters

New in the signed v0.3.0 development release: an HDR Composition section with Short, Medium and Long image selectors. Use linear masters of the same field, registered to a common reference, with different exposure lengths.

  1. Click each Browse... button to choose a single-image XISF or FITS master.
  2. Alternatively, click Auto-detect exposure groups and select one master per exposure length. FITS EXPTIME/EXPOSURE and XISF Instrument:ExposureTime headers populate the slots from shortest to longest. Missing or conflicting exposure metadata, duplicate files, ambiguous groups and anything other than three distinct exposure lengths are rejected. This does not stack individual frames or guess from filenames; use manual selection when headers are absent.
  3. Click Prepare HDRComposition. The helper checks file existence, matching dimensions and channels, exposure order when available, recorded stretch history and coarse image alignment. It asks you to confirm linearity and common-reference registration because metadata and coarse pixel checks cannot prove either, especially subpixel alignment.
  4. Review the three images and the pre-filled native HDRComposition interface. Unchanged open inputs are reused; inputs with unsaved changes are rejected. On cancellation or error, newly opened inputs are closed while existing windows are preserved.
  5. Execute HDRComposition yourself after inspection. Continue with the resulting linear HDR master in Workflow Manager.

Prepared settings

Automatic exposure evaluation enabled; binarizing threshold 0.90; smoothness 7; growth 5; replace large scales 0. Reject black pixels, generate 64-bit HDR and output composition masks are enabled. Previously open images are not automatically closed.

Preparation does not execute image processing. PixInsight 1.9.5 was verified to open the pre-filled interface, so a process-icon fallback is unnecessary on that installation. Synthetic FITS/XISF header reading, preparation, cancellation cleanup and all five dialog profiles passed. Real-image HDR execution and output quality have not been tested.

The existing Integration / masters → HDRComposition → Open tool shortcut also remains available for manual setup.

PixInsight 1.9.6 choices

  • Subframe analysis: ImageAnalysis measures, approves and weights subframes.
  • Plate solving: BlindSolver handles active-image/batch solving with a configured Gaia index; ImageSolver retains its full solution controls.
  • Registration: AstrometricRegistration supports deep-sky registration and per-filter mosaics. FeatureRegistration is for lunar/daylight images.
  • Mosaic preparation: Open native SpectrophotometricFluxCalibration or MultiscaleGradientCorrection; configure file batches, curves and MARS options in their own interfaces.
  • Diagnostics / logs: WBPPLogAnalysis inspects WBPP/FBPP logs and generates reports.

New choices require PI 1.9.6. Existing saved plans and tool defaults are preserved. Updated WBPP/FBPP and ImageIntegration features are configured in those tools. Opening a tool does not run processing or transfer session-plan paths.
